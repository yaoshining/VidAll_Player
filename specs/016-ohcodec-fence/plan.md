# 实施计划与宪章检查

从 main 的 794c533 开始，以检入的来源锁独立恢复 Phase30 A 输入，核对派生清单及原生库身份。先验证 mpv 的普通逐帧归还和关闭排空，再核对解码器的实际回调退役顺序。FFmpeg 生产者材料只读；需要改动其 hwcontext 或 ohdec 时向维护者报告。原阶段保留六库封存身份，2026-11-11 按新授权接入已交付恢复 SDK。

1. 直接编译派生源树中的生产函数，用可观测的 Vulkan、NativeImage 边界替身测试。正常转交、平台错误、已导出 FD 但等待失败、已有历史提交、完成未知以及关闭时的重入均须覆盖。用真实管道 FD 验证泄漏与重复关闭。红测必须指向具体断言。
2. 只对证实的异常路径实施最小修复。追踪 queue 锁和 UI 等待边界；单纯关闭 FD 不代表 GPU 已完成。GPU 无法返回的场景单列；现有独立宿主的 controlled-app-exit 契约继续独立验证。
3. 需要引入会话隔离时，先以故障注入验证主线程可返回、旧代资源保持隔离、新代可创建、达到上限不再累积资源。若受跨项目进程级锁存阻断，记录所在层及恢复前提。
4. 使用常规 iMac CI 产物构建实际消费包。先证明健康文件实际进入 OHCodec/Vulkan，再测试坏片返回、切集、回到列表、关闭和重开。记录同一 PID、阶段/错误、画面、声音、版本与输入哈希。真机未通过前不提交 PR。

宪章核对：保留既有 API 兼容下限和 TV 遥控返回行为，不为此新增权限；正常及仍有隔离名额的会话保留零拷贝硬解，仅名额耗尽时按 R4 允许新会话软件降级。规格 R1–R5 必须对应实现、自动化验证及设备证据；宿主替身与模拟器均不得计作真机通过。

平板复现后的实施约束：由 VidAll_Player 为零拷贝播放实例预留两个独立名额，正常释放后归还，无法证明安全时继续占用。第三个实例在名额耗尽时走软件解码；正常实例与隔离一个旧实例后的下一部片仍使用 OHCodec/Vulkan。旧实例的图形线程在故障现场停住，不执行父级析构。关闭工作由独立后台线程持有，前台等待有期限。把故障通知送给所属 mpv 客户端，只有该代失效；不修改未启用会话隔离的宿主的原有终局契约。

验收要求：同一 PID 的故障前后累计至少经过原退出期限，第二次播放使用不同的播放器与 Surface，有连续变化的画面、非零音频输出和 OHCodec 原生缓冲归还记录；坏片返回、逐帧替换故障和关闭等待故障分别核对。

普通操作超时不等于确定的 GPU 故障。退出请求有独立队列位置，即使前台等待超时也不能被取消；只有正常关闭实际返回才可回收名额。明确的 GPU 故障继续保留名额，不再进入普通销毁。测试须覆盖在途操作比前台期限更长、最终关闭成功后新实例重新取得硬解名额。
