# OHCodec/Vulkan 零拷贝播放故障与资源归还

目标宿主是 VidAll_TV。已确认坏 MP4 在 API 19 TV 模拟器进入解封装错误，返回列表后可以播放其他文件；当时使用软件解码。本变更关注硬解帧进入 Vulkan 后的故障。

- R1 保留原有正常零拷贝硬解和渲染能力。对同一播放会话，设备证据须同时包含 OHCodec 实际解码、Vulkan 渲染、成功映射 OHCodec 原生缓冲区。仅配置 auto 或选中 MPV 不足以验收。
- R2 持有缓冲区的一方必须能证明完成或按平台契约转交有效的同步 fence。等待超时、队列失败或所有权不明时，旧 buffer、导入纹理和 surface 不得释放或交给新会话。每个导出的、尚未转交的有效 FD 由持有方关闭一次。
- R3 播放页遇到故障后，用户能及时返回文件列表，主进程存活。另选正常片要有新画面、推进的媒体时间和实际音频输出。普通坏片与在零拷贝交接中发生的故障分别取证。
- R4 若需隔离未完成的旧会话，必须限制保留的会话与资源，抵御迟到回调，并验证达到上限时的可控降级。不能靠清除全局保护、假定 GPU 已完成或重启应用满足条件。
- R5 诊断区分 hold、导出 fence、等待、归还 buffer、解码器 Flush/Stop/Destroy，保留阶段、平台错误和操作起止。对外仅使用会话序号；不得传输原始地址或媒体身份。远端统计采集不属于本次变更。
