# OHCodec/Vulkan 零拷贝播放故障与资源归还

目标宿主是 VidAll_TV。已确认坏 MP4 在 API 19 TV 模拟器进入解封装错误，返回列表后可以播放其他文件；当时使用软件解码。本变更关注硬解帧进入 Vulkan 后的故障。

- R1 保留原有正常零拷贝硬解和渲染能力。对同一播放会话，设备证据须同时包含 OHCodec 实际解码、Vulkan 渲染、成功映射 OHCodec 原生缓冲区。仅配置 auto 或选中 MPV 不足以验收。
- R2 持有缓冲区的一方必须能证明完成或按平台契约转交有效的同步 fence。等待超时、队列失败或所有权不明时，旧 buffer、导入纹理和 surface 不得释放或交给新会话。每个导出的、尚未转交的有效 FD 由持有方关闭一次。
- R3 播放页遇到故障后，用户能及时返回文件列表，主进程存活。另选正常片要有新画面、推进的媒体时间和实际音频输出。普通坏片与在零拷贝交接中发生的故障分别取证。
- R4 若需隔离未完成的旧会话，必须限制保留的会话与资源，抵御迟到回调，并验证达到上限时的可控降级。不能靠清除全局保护、假定 GPU 已完成或重启应用满足条件。
- R5 诊断区分 hold、导出 fence、等待、归还 buffer、解码器 Flush/Stop/Destroy，保留阶段、平台错误和操作起止。对外仅使用会话序号；不得传输原始地址或媒体身份。远端统计采集不属于本次变更。

## 2026-11-11 接入上游关闭恢复

用户授权接入 ohos_ijkplayer PR #11 已合并修复，补齐当前 Player 的缺失验证。

- R6 消费合并提交 `32887363cb103163fe6557ca64c05539ad6d73f2` 绑定的无注入六库 SDK。校验归档、217 项清单、公开 ABI、mpv 使用的 FFmpeg 头及 SMB 资源；完整记录上游本地构建来源和 Player iMac CI HAR 来源。禁止把原 mpv 编译时使用的旧 FFmpeg 记录改写为新 SDK 编译证据。
- R7 在 API 24 平板使用新 SDK 与当前 Player 联合验证正常 A/B 播放、坏片返回、Vulkan 关闭错误后新会话硬解音画、延迟关闭最终回收名额及达到隔离上限后的降级。每轮包含同 PID、列表响应、媒体时间、变化画面和设备输出幅度。Stop/Destroy 的上游验收单列，消费端实测必须使用上游提供的注入库并明确替换项。API 19 TV 真机仍单独待验收。

- R8 新 SDK 消费组合复查 #89 的音频中断合同：API 19 TV 模拟器在闹铃期间和解除后保持暂停，进度不动、输出归零，用户一次播放后恢复音画；退出或换集后旧中断不影响新媒体。API 20+ 行为单独复查。

隔离上限说明：Player 的两个名额约束无法安全归还的 mpv/Vulkan owner。上游 FFmpeg 在 Destroy 返回错误时保留独立窗口和回调壳至进程退出；该资源不属于上述两个名额，不宣称已覆盖其持续故障耗尽或平台 Stop/Destroy 永久挂起。

- R9 owner 故障通知须独立于普通事件队列容量保存，保留首个 stage/error；NAPI 环境清理钩子返回前必须停止回调投递并释放 TSFN，不能等待 GPU 析构。宿主回归验证满队列和实际环境清理入口。
## 清理阶段补充约束（R10）

环境清理或释放超时后，已经排入 TSFN 的所有事件（包括 error）均不得再调用 JS；事件持有的关闭标记必须独立于 NativeSession 生命周期。封闭 JS 回调不能停止原生 owner 故障监听：关闭工作实际完成前仍需接收迟到故障并保留隔离名额。正常回调、替换回调、空环境回收与清理后的迟到故障均须有生产函数回归。

验收记录约束：离线诊断消费夹具与正式文件入口分开记录；音频幅度、原生解码/渲染日志、变化画面及 PID 证据须互相对应。为上传限制使用的小包须重新绑定素材、HAP 和原生库哈希，不能把拒绝安装或缺失阶段日志的包计作注入通过。API 20 消费端选集回归失败时，R8 保持未完成，单变量对照不能替代正式修复。

R9/R10 同样适用于未启用会话隔离的软件解码会话：即使有诊断工作持有引用或运行时已终局，清理入口也须同步封闭每个会话的回调；最后引用的释放不得在环境线程等待析构。后台析构无法启动时保留对象，不回退到同步 GPU 清理。

设备复验分层：T025 使用绑定当前 NAPI 桥的 CI HAR，在云平板实际销毁带活动软件会话的 Worker 环境，观察 UI 心跳、退出回调以及同 PID 后续硬解音画；阻塞析构和排队 TSFN 竞态仍由真实生产函数回归覆盖。此设备用例不替代永久 GPU 挂起测试。R8 的消费端状态修复独立跟踪 [VidAll_TV #371](https://github.com/yaoshining/vidall-tv/issues/371)，未完成前不得将 R8 标记通过。
