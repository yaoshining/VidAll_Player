## AAC 与静音闹铃

使用消费端原有的“验证 MPV 声音与打断”，先测播放、手动暂停与恢复，再由全零数据的闹铃流申请独立焦点。每阶段采样八次扬声器峰值。表内时间来自实际控制器，单位为秒。

| 模拟器 | 打断和解除后的状态 | 按一次播放后的进度 | 恢复峰值 |
| --- | --- | --- | --- |
| API 19 TV | 两阶段均暂停在 3.667，16 次采样全零 | 4.417 → 5.917 | 0.0102 |
| API 20 平板 | 两阶段均暂停在 3.667，16 次采样全零 | 4.583 → 6.000 | 0.0034 |

两台设备均未进入原始探针“先手动暂停再播放”的补救分支。API 19 使用新建测试实例，已有签名不同的应用及其数据保留。

## 换集与退出

API 19 使用同一主包和同一 CI 核心。独立测试模块额外控制闹铃的生命周期，SHA-256 为 `58b8db58899d36ae60e830be2b1079875f85954bc15143f885bad99c88c643a4`。

- 第一集被打断后停在 3.583 秒。闹铃解除后仍暂停，从真实播放器控件选“下一集”，第二集从 0.083 走到 1.417 秒，峰值 0.0107。
- 第二集被打断后停在 3.583 秒。在闹铃仍活动时退出播放器，然后解除闹铃并打开第一集，进度从 0 走到 1.167 秒，峰值 0.0105。
- 宿主测试另覆盖旧 AO 的通知在新 AO 或空 AO 上消费、重复 PAUSE/STOP、RESUME 和音量提示。以上设备结果仅对应本次模拟器与 CI 附件；未在实体 TV 复测。

## 直接首播对照

额外在 API 19 让电影从头连续播放，跳过原探针的手动暂停和恢复。此时启动同一静音闹铃后，电影仍有声且进度推进。音频策略服务的焦点表在闹铃存活期间仅列出 MOVIE 为活动焦点，没有列出 ALARM。此实验没有形成 #89 所报告的声音和进度停止。延后发起闹铃结果相同；仅在本地试验中给电影渲染器显式设置独立模式也未改变结果，因此交付包沿用原有焦点模式。播放器仅处理系统实际送达的 PAUSE/STOP。
