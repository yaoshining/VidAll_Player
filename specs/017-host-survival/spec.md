# 宿主存活与全局故障后续播契约

基线 main `fa27cbd346f1a745ffc1b5bfd57b4239c094327f`，与交付源 `27b7dba` 源码树相同。关联 VidAll_TV #370，独立于消费端 #371。

- R2 普通坏片、可归属的会话故障继续使用安全隔离，新实例及新 Surface 在有名额时保持零拷贝硬解；名额耗尽后的回退必须有界。
- R3 用户已确定：除R8明确限定的系统音频服务/驱动整体失效外，全局故障后也必须能继续播放，不能以禁用 MPV、等待用户重启作为验收结果。没有失败记录的视频优先尝试零拷贝硬解；硬解发生故障后，安全切换兼容路径。用户接受真正全局终局导致本次运行内后续播放暂用兼容路径，但重启后仅对记录的问题视频保留兼容选择，其他视频重新优先硬解；不得把单片失败持久化为所有视频的兼容策略，也不自动扩大到同编码格式的全部视频。其他视频日后独立失败时，再按同样流程处理。问题视频记录表示恢复选择，不表示已证明文件是根因。
- R3a 全局 OHCodec 终局不得清除锁存、绕过硬解创建禁令或释放完成未知的 GPU/Surface/解码器。本次进程进入终局后不承诺重新硬解；新进程中的正常视频恢复硬解不依赖清除旧进程锁存。兼容路径必须避开已确认失效的故障域；纯软件候选不能只是 hwdec=no 而继续初始化 Vulkan/EGL，实际模式及性能、格式边界须记录。
- R3b 切换过程中提示“硬解播放失败，正在切换兼容模式”；切换成功后才提示“播放失败，已切换兼容模式”。兼容路径也失败时显示明确失败状态并允许返回列表，不自动无限重试。每次打开最多自动切换一次；问题视频标识、记录持久化及容量上限须明确，不能用一次性授权 URL 作为唯一标识。故障后兼容续播仍须实测，无法满足时先报告限制，不以提示文案代替恢复实现。
- R4 清理关闭所有回调代，迟到事件不得进入已失效的 JS 环境；耗时操作不得永久占住 NAPI 公用工作池。初始化中、已注册及正在释放的实例都纳入资源上限，重复失败不能不断增加线程、队列或保留对象。
- R5 不更改 #83 尺寸更新、#84 旋转与完成通知、#89 音频中断合同；#371 不混入本工程通过结论。
- R4a 故障前的标准与兼容实例不得占用终局恢复预留名额：标准最多 6、故障前兼容最多 2、故障后新代兼容最多 2；隔离对象仍占原名额。达到任一上限明确失败并允许返回列表，禁止无界分配或强制回收。正常释放后的恢复名额可再次使用。
- R6 架构支持必须明确：现有完整核心仅 ARM64；x86_64 的旧 NAPI probe 不等于可播放实现，不得混旧桥或静默修改消费者架构。完整 x86_64 FFmpeg 需上游另行交付，禁止在本项目代建。

## 可验证场景与边界

- S1 未设置兼容模式且平台支持 GPU 时，原零拷贝硬解策略不变；禁用解码的旧选项不改变渲染语义。
- S2 显式兼容模式不进入 Vulkan/EGL/OHCodec interop，关键选项失败明确返回失败。CPU 写 NativeWindow 前必须等待 release fence，等待有固定总期限，错误或超时不得写入。
- S3 A 触发全局故障后能同进程返回列表并继续兼容播放；只对可靠关联的 A 记录，B 不因临时兼容而记错。重启后 B 恢复硬解优先。该场景已实现并通过软件路径终局注入；真实硬件故障及目标设备验证仍待完成。
- S4 连续故障、迟到回调、切集/关闭交错不能突破资源预算或影响新会话；旧音频不得与新片混播。该场景仍待 T004/T009/T013。
- S5 #83/#84/#89 回归及 API 19 TV 正式入口证据分别记录；不接受 API 24 或主机替身升级为目标设备通过。

- S6 故障身份须在可能执行原生加载前提供给宿主；快速切集、原生排队失败或拒绝加载不得导致两端加载代错位。故障通知独立于实例回调，A 的关闭失败不能标记当前 B；归属未知时不生成确定媒体标记。T024 宿主/NAPI 边界已通过，整链目标验证仍待完成。

- S7 进程终局通知只投递一次，投递后及终局后的同步重放不得保留订阅闭包；Player 释放成功或失败后均撤销运行期订阅，失败仍返回原错误，不宣称原生资源安全释放。覆盖重入、监听者异常、连续创建失败和未完成释放时的终局。

- S8 音频中断及恢复 CI 必须编译与交付核心一致的生产函数；旧流程不能遗漏恢复补丁，也不能将未执行的独立测试列为已覆盖。

- S9 首次观察终局即可拒绝旧操作，不等待完整元数据；完整记录发布后状态查询与晚订阅必须获得准确 stage/platform_error/归属，早订阅不重复投递。
- S10 原生向 JS 的事件队列也受资源上限约束；JS 暂停期间不阻塞生产者、不无限积压，高频快照可合并，当前媒体的关键失败和完成事件不能被进度洪泛挤掉。关闭与环境失效后只回收，不调用旧宿主；单个监听者异常不能阻断后续关键事件。队列溢出后，尚未启动的普通命令也必须拒绝，而安全释放仍可执行。
- S11 API 19 旧音频回调等待平台或数据时，不得持有跨会话登记锁。关闭先撤销该实例的回调入口，等待其已有回调结束后才允许释放 AO；这项等待不得阻塞其他实例登记、注销或迟到回调拒绝。
- S12 诊断核心保持与正式核心相同的公开 ABI；内部故障注入不能要求已移除的旧测试导出。静态验证仍须拒绝缺失恢复接口、额外公开符号与内部符号泄漏，并独立核对诊断注入存在；诊断检查通过不改变其非交付属性。
- S13 已确认 renderer 释放成功后，builder 清理失败或阻塞不得继续作为“旧声音未停止”阻止兼容续播。残留 builder、AO 和登记槽继续占用预算，直到实际安全清理完成；renderer 释放失败、未返回或状态未知时仍不得假报音频安全。
- S14 硬件验收探针首片必须以 standard 创建，并在首帧后核对实际 `hardwareDecoder=ohcodec`、`renderBackend=vulkan`；软件回退、copy 路径、缺失诊断不得记为硬件通过。硬件活动时的定时全局终局与 mapper 真实关闭接缝注入分开记录：前者验证旧硬件代退休后 compatible 续播，后者保留 owner 隔离并从保留帧验证故障归属、继续播放及隔离上限。所有注入只用于独立诊断包，不修改正常 HAR 或 FFmpeg。诊断验收包须与当前候选使用相同生产补丁基线；旧包的设备结果只保留为历史证据，不绑定到新候选。

S15：旧 renderer 的 Stop 调用已返回错误时，不得仅据返回码永久推断音频仍活动。可在相同所有权/控制锁内再次查询实际状态；仅明确 STOPPED 才能发布静止事实，仍 RUNNING、状态查询失败或 Stop 未返回均不得开放恢复。不得并发 Release、强制解锁、复位硬解锁或提前归还残留资源预算。

S16：宿主 CI 的工具准备可使用官方运行器镜像已有的 LLVM 18，但须逐项核对 clang/clang++/llvm-nm 的可执行性与版本，绑定到后续 PATH 并保留输出；缺失或不匹配仍使用原依赖安装失败门禁。不能以镜像文档或工具探测代替完整测试。

S17：云平板诊断 HAP 必须显式声明 `tablet`，保留 `tv`。允许使用官方 `compressNativeLibs` 打包选项以满足上传大小限制，但必须由独立验收工程重新构建、签名，解压后的九库与原始完整诊断 HAR 逐库一致；不得改写 HAR、裁剪库或替换旧桥。此选项不扩大正式 HAR 支持架构，上传、安装、实际硬解、声音及 API 19 TV 验收分别记录。

S18：正常 release 发起的 mpv 关闭也必须保留原生故障观察者，直到核心关闭完成或已记录 owner 隔离。不得先停止事件线程再触发可能失败的 mapper 关闭；明确隔离后不销毁旧 handle/Surface、不归还名额。关闭超过接口等待上限时 UI 继续运行，迟到故障仍可独立发布。

S18a：关闭 GPU 输出前先正常关闭平台音频输出。owner 隔离后的旧音频流不得保持 RUNNING 或与后续视频混播；仅看 AAC 轨道或播放进度不能证明该项。音频关闭阻塞或失败时不得强制释放，继续保留有界预算并报告失败。

S19：音频验收使用系统实际输出的内录，不能使用输入素材、解码器输出或 RUNNING 状态冒充。按同轮设备事件指定完整时间区间，分别检测故障前880Hz、恢复后440Hz、暂停及释放后的静音；静音、错误音、旧音混入和持续掉音必须判失败。声音文件与包哈希、PID、设备及录制来源绑定；分析器自身的合成音测试只证明检测能力，不证明设备声音。系统焦点竞争还须另行记录真实打断事件、暂停和解除后的恢复，普通 pause/resume 不替代系统打断。

S20：API20及以上现代音频回调也必须将系统PAUSE/STOP传入Player暂停状态；RESUME提示不自动恢复。切片/关闭后迟到回调不能影响新会话，已退休恢复代不得被旧回调操作。现代写入回调保留，注册失败必须拒绝初始化并回收登记。API19旧回调行为不得回退。

S21：独立系统内录工具须在设备画面上显示有界的录制阶段及系统状态，区分创建、初始化、禁用麦克风、启动调用返回、等待STARTED和清理。平台调用未返回不得假报完成或强制释放；阶段日志不包含素材路径，只保留最近12行，每行最多160字符。诊断显示不放宽录制开始门槛、超时或音频验收要求，不进入正式HAR。

S21 的可见阶段诊断同时适用于普通/焦点页、mapper 关闭故障页和 hardware-first 全局终局页；各页保留原有硬件资格、人工返回/继续和同进程证据要求。

S19/S20 验收说明：系统录屏确认成功和录制完成仅证明采集流程可运行；未导出的音轨不能计为声音通过。竞争源有采样但未出现暂停时须判失败，并分别核对系统焦点决策、原生回调、AO请求和Player状态，不能用直接调用pause替代系统打断。2026-11-13的当前候选Air复验仍有此失败，详见T047设备记录。


### S22：独立验收工具的故障与音轨导出

验收程序在播放前订阅本应用 OS/APP_CRASH，重启后展示有限的故障记录并保留可导出副本；不得读取其他应用或绕过系统目录权限。允许用户通过系统保存选择器导出停止后的测试内录、事件日志和崩溃记录；取消、文件不存在、读取/写入失败、尚未结束录制均不得报告成功。导出不代表声音或设备验收通过，不上传任何数据，不修改正式 HAR。以报告中的实际设备版本记账，禁止把 HarmonyOS 7 结果混入 API24。

S23：OHAudio写入与中断注册必须使用同一个受保护的用户数据token，兼容平台共用userData的实现；不得把token解释为AO指针。现代写入也须取得在途引用，注销后迟到回调只返回静音、不访问旧AO、不影响新会话。API19与现代回调的返回契约分别保留。

S24：现代中断符号查找不能假定系统库对RTLD_DEFAULT全局可见；可在API20+从已链接的官方libohaudio句柄解析，临时引用必须归还。缺库/缺符号/注册失败仍明确失败；API19不调用新接口，不把无音频输出的视频画面记为成功。


### S25：云验收录制授权的有界等待
独立验收工具等待系统STARTED的默认窗口为60秒，包含用户授权与远程控制往返；参数须有限且在1至60000毫秒内。超时、拒绝、迟到回调仍失败，start API返回不能冒充录制开始。此窗口不影响生产故障截止、清理/资源保护或声音验收。


### S26：独立证据的有界分块导出
仅显式操作导出本应用固定events.jsonl/capture.mp4，录制忙时拒绝。每文件最多16MiB、每块256KiB，携带版本、种类、总长、SHA256、块数和索引；接收方拒绝缺块、错序、重复冲突、截断和哈希不符。只使用云调试已有剪贴板同步，不增加服务端/权限，不读取其他应用、任意路径或剪贴板旧内容。离页取消、重复操作、读取失败和复制失败不可报成功；工具通过不代表听声通过。

T054设备反馈：生成的全局页须用Column分开导出控件与状态，避免Stack遮挡；第三会话录制至少2秒以容纳完整声音区间。故障流程cancelled只停止播放，证据导出仅在实际离页后关闭，失败记录仍可取回。仅验收工具变更，先回归后构建。

### T055 全局故障手动导航证据
独立全局诊断必须先显示播放失败，实际点击返回列表后才显示下一视频入口，再由手动点击触发新会话；自动推进、超时或退出不得冒充用户选择。单阶段最多等待60秒，超时保留失败证据。此工具变更不修改生产HAR。

### S27：永久音频挂起的分类与恢复证明
区分应用回调/锁互等、单renderer平台挂起与系统服务失效，不能仅凭超时认定根因。音频输出与视频会话分离仅为待验证方案；填零、固定等待或新输出创建成功不能证明旧音停止。重复故障资源有界且仍可播放才算通过。S18a生产关闭契约不变，新方案实施前补具体设计及红测。见[audio-recovery-options.md](audio-recovery-options.md)，普通/单实例故障仍不退出主应用、不永久禁播；系统音频服务/驱动整体失效仅按R8处理。

### R8 / S28：系统音频整体失效的退出例外（2026-11-14用户确认）
仅确认系统音频服务或驱动整体失效且无法恢复时，允许结束主应用；UI仍可用时优先提示，再由宿主执行受控退出。普通坏片、单renderer超时、应用锁互等、隔离额度耗尽、OHCodec进程终局不自动等同本例外。单次超时/返回码/新流失败不足以证明系统整体失效；诊断来源、判定准则、瞬态恢复和误判负例须先明确并测试，未确认则不得触发本例外。Player报告可判定的故障类别与证据，宿主负责提示和退出策略；不直接恢复无条件std::_Exit。系统本身失效时不能承诺重开应用即可修好，也不能保证UI已失效时仍能显示提示。

### S29：音画同步与最小版本范围
本轮定位须区分素材/分析、录制链路与Player输出：同设备同素材同录制配置增加独立系统AVPlayer对照，不将其结果用于替代MPV验收。原seek失败门槛保持，失败前保存完整诊断，并有界继续观察以区分暂态恢复与永久停滞；继续观察成功不得抹去原始失败。设备确认原因前不调整音频延迟补偿、不放宽门槛。关闭隔离每组完成证据导出后才换包，提前采集故障前PID和原生日志。
有界PCM队列只限制积压，不能独自保证同步；新队列须纳入音频播放时间/总待播帧计算，不能把入队视作已经播放或重复计入延迟。切片、seek、暂停恢复、倍速、欠载及输出路由变化须正确处理时间基准与旧代数据；时间戳停滞时不得无限外推。以真实音画标记测偏移和长播漂移，当前声音存在性证据不能替代同步验收。先定位是否需要新增队列，能窄修关闭/回调问题则优先窄修。
Stop/Release及输出路径为多个API版本共用，目前没有永久挂死仅发生于API19TV的证据。若证明缺陷仅在API19TV实现，则限制该设备/版本路径；共用代码缺陷做最小共用修复并覆盖API19及现代回调负例，不因历史TV目标而只屏蔽一端，也不无证据全面改造。

T056最小修复候选：实际回调红测确认违反平台接口约束，查询延迟还会使用过期now。优先把时钟查询移到每个已登记音频槽最多一个采样线程（总量受16槽约束），不新增PCM队列。查询与控制/释放共用槽锁，回调只读短锁缓存，缓存过期不无限外推；注销先撤销回调，再停采样并等待其退出，未返回继续保留对象/预算。停止/复位/路由变化和采样线程创建失败均须回归。仅代码级缺陷已复现，真机永久平台挂起根因仍未证明；不增加自动退出，API19/现代共用函数均受影响。候选实现与设备验收分别记账。

### S30：独立时间锚点与关闭声音完整区间
验收包在原始录制中叠加带校验的递增视觉时间码，记录请求更新时的单调时钟与墙钟；它独立于Player进度和firstFrame。录制前后以独立系统AudioRenderer输出已知帧位置的2200Hz脉冲，调用API19起支持的getAudioTimestampInfo读取实际播放位置与时间戳。平台查询只能在写回调外串行执行；无效、倒退、时基不符、超时、码重复/损坏、前后校准漂移均拒绝校准，保留资源与失败，不伪造成功。API15–18明确报告锚点不支持，不能用旧时间戳接口猜测帧位置。
时间码为UI提交时刻，须保留显示合成和采样的不确定度；平台播放时间戳也不替代物理扬声器/面板测量。原始偏差、锚点校准结果和物理验收三者分列，不把约150ms常量硬编码为补偿。关闭隔离每会话保留完整固定播放观测段，记录起播延迟、稳态音频、停止音尾、等待静音和串音；不能删去短片失败记录，不能自动寻找成功窗口。保持原关闭注入、独立故障归属、同PID、七秒late-close、名额回收及上限回退门槛。

静音区间按10ms固定分辨率测量RMS，避免将几十毫秒音尾扩大成整段200ms失败；不裁边界，不更改-55dBFS、95%覆盖与300ms连续失败门槛。播放测试音频率检测仍使用200ms。保留旧分辨率原始结果及新结果，先用短音尾、超标音尾和持续噪声负例验证分析器，再复算设备原始证据。时钟对齐使用独立校准，不由待验收播放区间拟合。

播放段最后不足200ms的统计块，频率测量使用以段尾为终点的完整200ms样本，覆盖率仍只计该块实际时长；防止数毫秒纯440Hz样本的频谱泄漏被误报880Hz混音。旧音须同时超过既有-55dBFS静音底线及-25dB相对功率门槛才记混播；低于静音底线的噪声不能冒充旧音，新音不足-45dBFS仍失败。短尾、低电平噪声和真实串音须同时回归。
