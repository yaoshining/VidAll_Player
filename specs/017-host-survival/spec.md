# 宿主存活与全局故障后续播契约

基线 main `fa27cbd346f1a745ffc1b5bfd57b4239c094327f`，与交付源 `27b7dba` 源码树相同。关联 VidAll_TV #370，独立于消费端 #371。

- R1 VidAll_TV 使用显式、不主动结束宿主进程的初始化契约；播放器故障显示失败状态，返回列表不依赖原生析构完成。
- R2 普通坏片、可归属的会话故障继续使用安全隔离，新实例及新 Surface 在有名额时保持零拷贝硬解；名额耗尽后的回退必须有界。
- R3 用户已确定：全局故障后也必须能继续播放，不能以禁用 MPV、等待用户重启作为验收结果。没有失败记录的视频优先尝试零拷贝硬解；硬解发生故障后，安全切换兼容路径。用户接受真正全局终局导致本次运行内后续播放暂用兼容路径，但重启后仅对记录的问题视频保留兼容选择，其他视频重新优先硬解；不得把单片失败持久化为所有视频的兼容策略，也不自动扩大到同编码格式的全部视频。其他视频日后独立失败时，再按同样流程处理。问题视频记录表示恢复选择，不表示已证明文件是根因。
- R3a 全局 OHCodec 终局不得清除锁存、绕过硬解创建禁令或释放完成未知的 GPU/Surface/解码器。本次进程进入终局后不承诺重新硬解；新进程中的正常视频恢复硬解不依赖清除旧进程锁存。兼容路径必须避开已确认失效的故障域；纯软件候选不能只是 hwdec=no 而继续初始化 Vulkan/EGL，实际模式及性能、格式边界须记录。
- R3b 切换过程中提示“硬解播放失败，正在切换兼容模式”；切换成功后才提示“播放失败，已切换兼容模式”。兼容路径也失败时显示明确失败状态并允许返回列表，不自动无限重试。每次打开最多自动切换一次；问题视频标识、记录持久化及容量上限须明确，不能用一次性授权 URL 作为唯一标识。故障后兼容续播仍须实测，无法满足时先报告限制，不以提示文案代替恢复实现。
- R4 清理关闭所有回调代，迟到事件不得进入已失效的 JS 环境；耗时操作不得永久占住 NAPI 公用工作池。初始化中、已注册及正在释放的实例都纳入资源上限，重复失败不能不断增加线程、队列或保留对象。
- R5 不更改 #83 尺寸更新、#84 旋转与完成通知、#89 音频中断合同；#371 不混入本工程通过结论。
- R4a 故障前的标准与兼容实例不得占用终局恢复预留名额：标准最多 6、故障前兼容最多 2、故障后新代兼容最多 2；隔离对象仍占原名额。达到任一上限明确失败并允许返回列表，禁止无界分配或强制回收。正常释放后的恢复名额可再次使用。
- R6 架构支持必须明确：现有完整核心仅 ARM64；x86_64 的旧 NAPI probe 不等于可播放实现，不得混旧桥或静默修改消费者架构。完整 x86_64 FFmpeg 需上游另行交付，禁止在本项目代建。
- R7 最终原始 HAR 从本工程 CI 交付，记录源提交、运行器、HAR 与各库哈希、架构、迁移步骤。主机、模拟器、真机证据分层；API 24 不代替 API 19 TV 正式文件入口。

## 可验证场景与边界

- S1 未设置兼容模式且平台支持 GPU 时，原零拷贝硬解策略不变；禁用解码的旧选项不改变渲染语义。
- S2 显式兼容模式不进入 Vulkan/EGL/OHCodec interop，关键选项失败明确返回失败。CPU 写 NativeWindow 前必须等待 release fence，等待有固定总期限，错误或超时不得写入。
- S3 A 触发全局故障后能同进程返回列表并继续兼容播放；只对可靠关联的 A 记录，B 不因临时兼容而记错。重启后 B 恢复硬解优先。该场景已实现并通过软件路径终局注入；真实硬件故障及目标设备验证仍待完成。
- S4 连续故障、迟到回调、切集/关闭交错不能突破资源预算或影响新会话；旧音频不得与新片混播。该场景仍待 T004/T009/T013。
- S5 #83/#84/#89 回归及 API 19 TV 正式入口证据分别记录；不接受 API 24 或主机替身升级为目标设备通过。

- S6 故障身份须在可能执行原生加载前提供给宿主；快速切集、原生排队失败或拒绝加载不得导致两端加载代错位。故障通知独立于实例回调，A 的关闭失败不能标记当前 B；归属未知时不生成确定媒体标记。T024 宿主/NAPI 边界已通过，整链目标验证仍待完成。

- S7 进程终局通知只投递一次，投递后及终局后的同步重放不得保留订阅闭包；Player 释放成功或失败后均撤销运行期订阅，失败仍返回原错误，不宣称原生资源安全释放。覆盖重入、监听者异常、连续创建失败和未完成释放时的终局。
