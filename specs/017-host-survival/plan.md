# 实施计划与安全边界

用户已确定 R3：全局故障后仍需播放；本次运行可暂用兼容路径，跨重启仅保留问题视频的选择，其他视频重新优先硬解。不得把“删除 _Exit”或“停止 MPV 等重启”作为完整修复。现有终局仅直接拦截 OHCodec interop，不能未经验证将其解释为整个 mpv 软件路径均不可恢复。

1. 原样编译当前 process_runtime 与既有测试，复现 deadline 的退出码和时间；核对原始 HAR 的九库与架构。
2. 区分三类生产入口：未启用 owner 隔离或 client_api 不存在的 owner_fault；与全局关闸并发的 Vulkan 创建收尾；正常受保护实例的局部故障。检查派生源码与生产编译输入一致，不把诊断宏分支算作发布路径。
3. 先验证恢复路径可行性，再补完整红测：非退出策略在多倍旧期限后仍有 UI/调用方心跳；终局事件只报告一次，旧代排队及迟到回调关闭；所有在途/排队请求有界返回；终局后硬解创建仍拒绝，只有通过恢复能力校验的新代软件会话可启动；重复失败/上限/安全降级。
4. 增加显式策略的 ArkTS→NAPI→native 传递及配置冲突检测。为主 UI 提供确定的错误/不可用状态。隔离未归还的资源，不重置进程锁存。关闭安全门与线程/队列/实例总上限共同实现，不能仅增大 deadline。
5. 回归尺寸、旋转、完成通知与音频合同；独立消费者覆盖正常、打断/手动恢复、切集、退出重开、坏片返回、新片播放与连续故障。错误注入与真实平台故障分别标明。
6. 先本地验证，再 iMac CI 构建完整 HAR；准确说明 ARM64 支持边界及 x86_64 的缺失能力。交给 VidAll_TV 从 API 19 TV 正式入口验收，未获得记录前保持待验。

软件恢复的可行性门槛：新 mpv 实例固定 hwdec=no、gpu-hwdec-interop=no、vo=libmpv、MPV_RENDER_API_TYPE_SW，不探测或升级 EGL/Vulkan；使用新 Surface/回调代，旧代永久保留规则不变。必须证实旧音频停止且不与新片重叠、旧代不再控制音频焦点、旧代不会卡住共享工作池、新代能够正常释放并反复重建。不能仅凭源码调用图通过此门槛，也不能把当前“软解 + Vulkan”的上限回退当作该路径证据。

若上述门槛失败，再评估独立后端；AVPlayer 的格式/轨道/字幕/网络能力差异须显式记录，不能用其支持的单个 MP4 替代完整 MPV 兼容性。API 19 TV 的普通应用子进程受官方设备类型限制，不以平板成功作为 TV 支持结论。

宪章初步检查：不新增宿主退出权限、不绕过原生所有权安全门、不在 UI 执行同步等待、不混入 FFmpeg 项目改动。平台进程隔离能力尚未验证，本方案不承诺以 API 19 不支持的应用子进程解决问题。资源上限数值及跨 NAPI 环境的归属/计数设计须在实现前明确，不能把当前两个 OHCodec 名额当成所有软件会话和 FFmpeg 残留的总上限。

## 恢复策略与记录范围

先以测试表达：新视频默认硬解；局部可隔离失败不影响其他视频硬解；真正全局终局后本进程保持硬解禁令并安全启用兼容路径；重启后问题视频走兼容，其他视频仍硬解；另一个视频独立失败时按相同流程处理。会话临时回退不得写成所有后续视频各自的失败记录，只有实际发生相关故障的视频才记录。关闭时故障使用旧会话媒体标识，不能误记为正在打开的新视频。

持久化记录采用有界容量和稳定媒体身份；内容更新及用户手动重试的清除规则须在实现前明确。不得保存含凭证的原始媒体 URL。记录是避开已失败路径的策略，不是文件损坏的归因结论。兼容成功、兼容失败、重启、连续故障和记录上限均应覆盖，提示“已切换”必须与实际切换成功一致。

## 实现切片与审查记录

先完成 T012 显式 compatible 模式作为独立可验证基础：ArkTS PlayerOptions → bridge → NAPI CreateSession → Initialize；在选择渲染器前固定 CPU 路径，配置失败返回错误。第二阶段 T013 建立可靠会话关联；T009/T004 先证明音频与工作线程安全后才开放非退出策略。架构见 contracts/player-recovery.md，状态见 data-model.md，宪章与需求一致性见 checklists/constitution-and-consistency.md。T012 不是全局恢复的替代验收。

## 软件兼容路径的 fence 前置修复

源码审查发现 SwRenderLoop 未等待 RequestBuffer 返回的 release fence 就 CPU 写入，并把同一 fence 交给 FlushBuffer。依据 [官方 NativeWindow API](https://developer.huawei.com/consumer/en/doc/harmonyos-references/capi-external-window-h/) 与 [OpenHarmony NativeWindow 指南](https://github.com/openharmony/docs/blob/master/en/application-dev/graphics/native-window-guidelines.md)，生产者须先等待 release fence，并在不再使用时关闭；CPU 同步写完后提交 -1，不能复用 release fence。

T014 先测试真实 SwRenderLoop：已就绪 fence、未就绪超时、错误 fd、RequestBuffer 失败及原暂停 resize/Flush 重试。实现固定总计 50 ms 的 poll 等待（EINTR/EAGAIN 不重置期限），失败时不读取/映射/写入缓冲区，归还已申请的 buffer 并上报失败；正常路径关闭 release fd 后 CPU 写入，再以 -1 提交。无新平台 API，NativeWindow 相关接口自 API 8 可用。此等待仅在渲染线程，不占 UI；不证明 NativeWindow 自身调用永不阻塞，整体预算仍由 T004/T009 负责。

## 异步队列收敛

T015：每个 ArkTS 会话最多接纳 64 个在途及排队命令；超过返回 COMMAND_QUEUE_FULL，不创建额外执行链。终局关闭队列时，立即拒绝所有公开 Promise，未执行任务不再启动；已经进入 native 的操作仍由原生层持有，不能把 JS 拒绝当作原生资源释放。正常操作保持串行和错误后可继续。晚到完成不得重新兑现已拒绝的请求。此项不是原生线程预算的替代。

T016：创建 mpv 前申请会话预算，standard 最多 6、compatible 独立保留 2。预算覆盖初始化、已注册、后台析构和隔离保留状态，只在真正析构后归还。硬解原有 2 名额另行保留。超额返回 SESSION_RESOURCE_LIMIT，不创建对象、不退出宿主。兼容池用于避免标准会话占满所有创建额度；软件本身也连续发生不可释放故障时仍必须有界拒绝，不伪造资源归还。此上限仅限定会话数量，不代替原生任务队列及音频安全门。

## mpv 音频隔离设计

T017 在 Player 管理的 mpv 扩展中增加实例代与有界音频登记表（16 项）。mpv 实例创建时捕获代，首次全局终局推进进程代；旧代不能再创建/启动音频，写回调立即停止提供旧声音。音频初始化先登记 BUILDING，完成 GenerateRenderer 后才发布，避免初始化与终局竞争被漏计。

停止旧 renderer 由独立恢复工作线程执行，不从终局 handler 调用 mpv core/VO，也不持登记表全局锁调用平台。每个 renderer 的 Start/Pause/Stop/Release 用自身控制锁串行；回调不拿此锁，避免 Stop 等回调死锁。恢复准入必须观察到所有旧代音频已停止或安全释放；不能将静音等同于焦点已释放。Stop 失败/阻塞保留占用并上报恢复未就绪，不假装成功。API 10 已有 OH_AudioRenderer_Stop/GetCurrentState，符合 API 19；依据官方 native_audiorenderer.h 文档核对。真实系统焦点和 Stop 延迟仍待设备验证。

登记 token 含单调身份及槽索引，旧 token 不能操作复用槽。真正 Release 完成后才清空槽。新代与旧代控制锁分离；宿主快照不等待单个 renderer 的平台调用。该模块由本工程集成到 mpv，不修改 FFmpeg。

T018：native runtime 新增 preserve-host 策略，启用前校验独立恢复 ABI，旧核心不支持时拒绝初始化。旧 controlled-app-exit 默认契约保留用于兼容与回归。独立恢复线程执行旧音频停止，monitor 保持有界观察；非退出策略绝不执行 _Exit。终局后旧会话继续拒绝操作和保留 GPU 资源，只有“新创建、纯软件、音频已静止”的恢复代获得准入。超过原截止时间只报告恢复尚未就绪，不杀宿主、不重置硬解锁。原生内部先验证，再贯穿 NAPI/ArkTS；没有完成逐会话准入前不公开新初始化选项。

T004 执行池切片：除原有 2 个硬解隔离线程，普通软件会话使用独立 6 名额执行池，兼容会话使用独立 2 名额执行池。每个实例同时最多一个在途操作及一个待关闭任务，等待调用方最多 5 秒，超时不归还后台实例/线程名额。硬解池耗尽时不把软件工作直接放入 NAPI 共用线程执行。工作请求入口仍需另加总排队预算；此执行池切片单独通过不能视为总预算已完成。

原生入口排队预算：常规操作/诊断共 32 项，关闭预留 8 项，恢复通道预留 8 项。预算覆盖 NAPI 队列、执行中的独立任务以及超时后仍在运行的后台操作；只有所有引用结束才归还，不随公开 Promise 超时清零。常规、关闭、诊断与恢复预留已接通；创建本身的专用执行和跨环境生命周期仍待审查，不能提前宣称总预算和全局设备恢复完成。

跨环境生命周期：每次 NAPI 环境建立独立的共享存活标识，清理时先关闭标识，再处理仅属于该环境的会话。环境指针被系统复用时创建新的标识；旧清理不能删除新登记。原生 handle 只允许由所属环境访问。创建任务捕获标识，在发布 handle 的同一临界区确认环境仍存活；清理期间完成的创建不得进入全局会话表。已关闭环境的异步完成不再创建 JS 对象或兑现 Promise；由平台调用的 complete 仍归还 napi_async_work，避免清理路径泄漏。此区别依据 OpenHarmony native_async_work.cpp 的完成回调及 native_engine.cpp 的 CleanupHandles 顺序核对，目标版本仍需运行期复验。旧终局实例仍保留预算与资源，但不再匹配新环境。

创建执行切片：创建前取得会话预算及相应标准/兼容执行名额，mpv_create 与初始配置在该独立线程执行，NAPI 工作线程最多等待 5 秒。创建票据与 handle 发布共用会话表锁；超时/取消先撤销票据，同时收回已发布但尚未交付的 handle。迟到构造只允许安全回收或按旧终局策略保留，不再发布。初始化的软件实例复用该线程，硬解实例切换到原隔离线程；释放前不回收仍运行的线程名额。该方案不增加无限后台线程，也不复位硬解安全锁。

恢复额度修正：故障前的 compatible 会话也会变成旧代，不能让它们占满全局故障后的恢复容量。会话及执行名额分为 standard 6、故障前 compatible 2、终局后 recovery 2，总数最多 10（硬解隔离仍另限 2）。恢复名额仅允许固定创建代为 2 的纯软件会话申请；不能由宿主通过 playbackMode 在正常期提前占用。旧代资源持续保留时，新代仍有两份独立额度；新代自身达到上限则有界拒绝。工作队列原 32/8/8 不变。

运行期配置执行：配置可能等待文件系统或 SDK 初始化锁，不能永久占用 NAPI 工作线程。全进程使用唯一配置执行器，独立名额 1，不占会话恢复额度；调用仍受 32 项常规请求预算和 5 秒等待上限约束。超时后实际配置继续受原预算保护，状态查询可报告配置中，重试不得启动第二个配置线程。

音频数据回调的退休检查覆盖进入回调、可能阻塞的时间戳 IPC 返回后、读取数据完成后三个边界。IPC 期间退休时不再进入旧 ao_read_data，已读出的旧数据用格式正确的静音覆盖；U8 静音为 128。此机制只阻止旧数据送出，不替代 Stop 完成和系统焦点验收。

T013 故障归属实现方案：新增 mpv 扩展加载入口，把 Player handle 与 loadGeneration 绑定到具体异步 loadfile 命令；不能先更新一个“当前媒体”字段再调用普通命令。命令生成的 playlist entry 保存加载代，真正开始播放该 entry 时发布解码上下文；decoder 创建时捕获不可变身份，输出 mp_image 保留身份，属性复制也传播。OHCodec drain/retained 故障只读取被保留的 last_src 身份，不能以 mapper->src（候选新帧）、当前 entry、Surface generation 或 owner_tag 补猜。晚到的 A 帧失败即使 B 已开始准备，也只关联 A。经过未保留元数据的路径则降为 unknown。

全局 terminal record 内部增加数值会话/加载代，同一次首次发布固定；旧公开 terminal ABI 不改布局，恢复 ABI 提供独立快照。创建回滚 LATE 无可靠已使用帧，明确 unknown。可隔离会话故障消息携带同样字段。宿主可据不可变身份记录实际失败视频，错误仍让当前不可用会话进入失败状态，但二者不可混为“当前视频是根因”。不携带 URL，不修改 FFmpeg。

关闭期间的故障不能依赖旧实例 TSFN：Release 已关闭实例回调时，原生事件线程仍将归属事实写入独立运行期故障历史。历史最多 16 条，仅含递增序号、故障范围、stage/platform_error 和数值身份；公开运行期轮询/订阅按序号去重。此通道报告故障事实，不恢复旧实例，不向失效环境回调，也不持久化媒体标记。已释放的 Player 事件不能承担 TV 标记所需的唯一通知。

T024 待实现：PlayerSession 在校验通过并推进加载代后，经 bridge 等待原生会话创建，先向宿主交付 sessionId/loadGeneration，再提交带相同加载代的原生 load。原生入口接收显式加载代，排队拒绝也不能让下一次两端计数错位；旧五参数调用继续兼容。身份交付先于原生调用，避免故障后 TSFN 已关闭而无法补交。TV 按此身份回执绑定稳定媒体 ID，不用当前页面逆推。

T024 公共调用采用向后兼容的可选第二参数：`load(source, onIdentity?)`。每次调用的回调闭包直接绑定对应稳定媒体 ID，不让宿主根据全局页面状态猜测。回执的 sessionId/loadGeneration 为只读十进制字符串；回调同步执行，必须在其中同步建立映射，异常则以 LOAD_IDENTITY_REJECTED 拒绝本次加载且不提交 mpv。回调之后再检查运行代。PlayerSession 显式传递已推进的加载代，NAPI 六参数入口校验 JS 安全整数；旧五参数保留自动递增。允许跳过被队列拒绝或回调拒绝的加载代，拒绝回退/复用及溢出，不改变旧完成事件的身份判断。

T025：完整门禁暴露多个终局观察者竞争。先以阻塞归属快照的确定性测试验证：首写者未发布完整记录期间其他线程不得返回 ready 或放行旧代，且不得等待首写者。完整记录仍以独立 release 标志发布，音频恢复等待完整记录；父级计时用例等待有限时间获取实际首次观察时间，不把 0 当作时钟原点。

完整目标编译发现 vo_gpu_next 的无 mapper 关闭路径仍调用 owner 入口；T013 补保留该入口并显式报告 unknown，不能借 owner/current entry 推测媒体。先补入口测试，复用故障投递逻辑，再完整重建。

T026：API 19 TV 模拟器安装的 HAR 九库匹配，但初始化返回 RUNTIME_RECOVERY_UNAVAILABLE。新增局部加载/全局符号不可见回归；恢复符号必须从已链接的实际 mpv 映像解析，不能仅依赖 RTLD_DEFAULT。以 dladdr 定位已有 terminal ABI 所在映像，再用 RTLD_NOLOAD 取得句柄，禁止加载另一份核心；Load 扩展共用同一解析规则。

目标探针分层：先用正常本地 HAR 验证 API 19 模拟器的 compatible 坏片/重开；再由 Player 独立工程构建仅诊断的进程终局注入 HAR，真实执行代退休/旧音频停止/新 Surface 软件播放。注入不模拟 GPU 错误，不能替代 OHCodec/Vulkan 真机与 API 19 TV 正式入口。正常 CI 包永不混入诊断库。

T027：先以真实运行期模块的测试计数观测订阅存活，复现一次性通知及释放失败后残留。投递前从全局表移走本批终局监听者，允许重入重放且每项一次；释放 Promise 结算后取消 Player 的终局订阅，不释放隔离原生对象、不吞错误。

T028：旧 test-player 工作流仍以未含恢复补丁的 mpv 音频源运行已更新测试。先复现缺少生产函数的失败，再让派生源覆盖与交付相同的音频改动，并将真实音频数据/控制/生命周期函数回归接入 CI；核对源摘要，不能只让替身测试自行通过。该变更不重建 FFmpeg，不改变音频恢复契约。

### T057：实际录制的音画同步测量

T059定位计划：先为独立系统播放对照的资源释放、失败/取消与seek失败诊断保留行为建立红测；系统AVPlayer仅用于验收页，不加入Player HAR。使用同一180秒标记素材、同一录制配置，分别保存系统播放器与MPV全段事件/音视频。记录原始轨道PTS和起止差，不凭轨道长度差直接认定录制延迟。seek保留700ms/250ms门槛，失败后先留完整快照，再每500ms有界观察10秒，最后仍报告原始失败。只有对照与设备证据指向实际缺陷后才先补生产回归、做最小修复。

T059判定修正：mpv 在 seek 未完成时可能用 `last_seek_pts` 显示临时目标；以该值作为推进起点，会把回落至前一个关键帧后的正常播放误判为停滞。先补临时目标回落、正常推进、永久停滞、错误目标、暂停/缓冲及非法诊断回归；在原三秒目标等待预算内，观察相邻快照实际推进后再执行原700ms/250ms门槛。失败仍保留原始快照及有界后续观察。此项仅修改验收工具，不改生产 seek 行为。系统对照也出现约150ms偏差，仍不能直接归因于录制或实际输出，不新增生产补偿、不抹去80ms原始门槛失败。
