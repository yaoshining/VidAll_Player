# Spec 019 · 实施计划

1. 从事故 HAR 对应的 main 提交和锁定的上游 mpv 定位坐标来源。建立直接使用 MPV_RENDER_API_TYPE_SW 的回归，验证首帧方向及后续像素变化。
2. 按当前渲染后端的能力建立 libmpv VO 的能力声明。软件后端委托 mpv 现有自动旋转过滤器产出旋转后的像素，再按帧尺寸缩放裁剪。GPU 后端继续提供自身的旋转和翻转能力。
3. 重用封存的正常核心构建输入及现有 FFmpeg SDK，只重建 mpv。校验公开 ABI、其他运行库、编译参数和输入及产物摘要。
4. 由同仓分支 iMac CI 封装完整 HAR。使用原 HAR 构建 TV #372 并在 API 19 TV 模拟器执行正式入口对照。

## 宪章与一致性

- 缺陷位于原生 mpv 视频输出。保持 HarmonyOS API、ArkTS 状态、权限和遥控器入口。
- 复用 mpv 既有过滤器和渲染资源管理。能力仅在各 VO 初始化时设置，由该实例持有。无新增线程、全局状态或应用层错误屏蔽。
- 保持原裁剪断言并在基线验证红测，绿测须检查可见方向和连续渲染。
- 分别记录目标库预验证、CI HAR 和消费端运行证据。
