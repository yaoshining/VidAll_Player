# 功能规格：正常核心组合最小接入 Player

分支：`codex/004-normal-core-integration`。创建日期：2026-10-23。状态：实施与本地验证完成，最终独立审查及远端 CI 待完成。基线：[baseline.md](evidence/baseline.md)。

## 用户场景与验收

### US1（P1）在独立宿主用完整正常组合播放

宿主从 `@vidall/player` 根入口配置私有运行目录与终局策略，再使用现有 Player API 播放；字幕、音轨、渲染后端和 diagnostics 行为延续基线。

验收：初始化成功后才可创建 native 播放器；NAS 使用应用私有目录下的运行配置和资源。相同配置重复初始化幂等，不同配置明确失败。目录不可写、资源缺失、ABI 不符或核心配置失败时拒绝播放，不能在半初始化状态进入硬解。多个 Player 实例共享一次进程初始化，不得反复覆盖配置。

### US2（P1）不可安全恢复时由明确选择的宿主受控结束

用户已接受“提示故障后结束整个应用、重新打开恢复”的最小方案。此授权仅允许独立消费者验证；本轮不改 TV。宿主必须通过公开配置显式选择此策略。SDK 不得在未配置时静默杀宿主；缺少策略应在创建/播放前返回初始化错误。

验收：首次 terminal 记录锁存进程级 fatal；全部实例拒绝后续播放、seek、命令、普通 release，诊断和状态使用缓存或快速错误。操作不得排在已挂起 commandQueue 后，不得再进入 lifecycleMutex、join 或任何 mpv 调用。发出一次公共致命事件，宿主展示中文故障提示并结束应用；独立 native 截止计时即使 ArkTS 事件循环、回调或日志堵塞也能完成已明确授权的进程退出。普通释放与非终局错误沿用原契约。

### US3（P2）可审查地交付独立 HAR

完整新组合 8 个运行库、公开头文件、静态 libplacebo 输入、源码锁、补丁、工具链和许可证索引绑定到同一清单。消费者真正引用新 HAR，不直接链接诊断工程实现。

验收：实际消费 HAP 包内 9 库身份可核对；缺库、错库、测试宏和 ABI 不符均被自动门禁拒绝。两次 clean HAR 构建逐成员及整体结果记录差异，不删除失败记录。旧候选保留，`formalArtifactAllowed=false`。

## 功能要求

- FR01：仅独立 Player 分支可改动。TV、原 Player 主工作树、旧候选、默认 SDK、producer 历史封存只读。
- FR02：公开异步初始化 API 接收应用上下文与终局策略；应用私有目录资源由 SDK 按版本管理，配置成功先于 `mpv_create` 和 SMB context。
- FR03：进程配置不可重置；相同规范化参数幂等，不同参数拒绝。并发初始化只能有一个提交者，失败结果对所有实例一致且不允许继续创建。
- FR04：公开 terminal 记录只含阶段、平台错误、时间和非敏感标识；全进程一次事件，迟订阅者可获取缓存 fatal。API 不暴露日志地址、凭据或私人媒体路径。
- FR05：fatal 检查必须在 ArkTS 队列入队前、native 锁前及异步工作执行前；已入队工作结束后不能覆盖 fatal。缓存快照不得继续同步读取 mpv。
- FR06：native 终局监听、截止计时与退出必须不依赖 UI 线程或 mpv 锁。宿主显式配置受控退出及截止时间后方可启用；默认不隐式启用。
- FR07：实际桥接普通命令/释放不得长时间阻塞 UI；本轮涉及的初始化、命令和 release 必须验证真实 native 与 ArkTS 接缝。正常 release 完成资源释放，terminal release 立即给出受控错误而不执行常规销毁。
- FR08：保留 `getDiagnostics`、DiagnosticField、firstFrame surfaceGeneration 及现有字幕/音轨/音频行为。禁止复制诊断程序的 `ao=null`、禁字幕、强制字体或测试场景参数。
- FR09：只绑定 Phase31 已验证 Phase30 A TRACE-only 正常组合；禁止 TEST、DIAGNOSTIC、EXPERIMENT 故障宏。保留 Python 目标路径修复，不追旧库哈希。
- FR10：target22/compatible15 不变。审核新库符号所需 API 级别；高版本能力要有显式门控/受控拒绝，不允许未说明的低版本加载硬依赖。API24 真机成功不等于旧 API 成功。
- FR11：独立消费者仅通过 `@vidall/player` 根入口和 HAR 接入；初始化、短播放、成功 seek、暂停恢复、关闭重开、终局接管纳入验收。故障注入必须标识为注入，不冒充真实 GPU hang。
- FR12：只使用应用保屏，不改变系统设置；未验证 GPU 永不返回、强并发极端交错、物理 HDR 等持续待验收；60 分钟长播不作为前置。

## 成功标准

- SC01：真实函数测试先 RED 后 GREEN，覆盖 FR02–FR07 的正常、失败、并发边界和队列堵塞；变异负例能识别终局后误入 mpv/锁或销毁。
- SC02：公开接口/ABI/来源锁/完整库包门禁可离线重放；双 clean 构建与消费 HAP 身份均留证。
- SC03：目标 ArkTS 编译和 native 构建通过，独立实际 HAR 消费工程正常路径及终局接管结果分层记录。
- SC04：最终材料含未验收项、TV 后续最小适配清单、精确提交 SHA/范围/字节推送预览，未经该 SHA 批准不推送。

## 已授权例外

宪章“错误可恢复”对 GPU 完成状态未知的 terminal 不可成立。用户已明确接受提示后受控结束应用；替代措施为显式宿主 opt-in、快照、原生 deadline 和全进程拒绝继续播放。该例外只覆盖不可恢复终局，不扩大到普通播放错误，不修改权限拒绝行为。
