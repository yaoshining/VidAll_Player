# 研究与 Spike 结论

## 状态声明

本文件只定义研究方法、决策材料和停止条件。三个决策门禁均未关闭；因此不存在任何“已支持”的设备、API、媒体输入、HAR 原生产物加载方案或 Surface/XComponent 生命周期承诺。

所有能力结论只可使用以下三态：`已通过真机样本`、`已构建待验证`、`不支持或暂缓`。本阶段的默认结论为后两态；NAPI probe、ArkTS 内存状态机、构建成功、库单独可加载、Promise 成功或合成事件均不能升级为真机播放或首帧证据。

## 决策 1：目标 ARM64 TV / API 与复现规则

- **决定**：在负责人书面确认前，不设正式支持矩阵；仅建立不预设机型的真机证据模板与研究性复现流程。
- **理由**：规格要求确认具名目标 TV、系统/API、样本数量和跨设备复现判定规则后才能作出支持声明。宪章还要求 API 15 为安装兼容下限、API 19 需核验敏感 API、API 19--22 策略明确。
- **候选方案**：
  - A：具名 TV/API 矩阵，全部设备复现每项能力；证据最强，但验证成本最高。
  - B：具名代表机和最小复现数量，其他设备明确未声明支持；推荐作为负责人可选择的最小正式基线。
  - C：只进行研究性取证，不设正式支持基线；适用于设备条件不足时。
- **负责人必须确认**：设备型号、ARM64 证明方式、系统版本/API、样本数、复现范围、首期媒体样本闭集、能力从“已构建待验证”升级的判定规则。
- **最小证据记录**：HAR 候选标识、源提交、设备匿名标识/型号/ABI、系统/API、媒体样本 ID 与摘要、执行人/时间、操作序列、预期与实测、事件序列、首帧佐证、错误与释放结果、日志/截图/录像引用、限制、三态结论和审批引用。
- **停止条件**：未取得负责人确认；未在指定真机取得首帧、播放、失败和释放记录；仅能在模拟器或 Previewer 复现；需要修改 VidAll_TV；或存在 AVPlayer 使用/回退。

## 决策 2：libmpv.so 准入与联合审计

- **决定**：加载位置与策略保持待定；候选 HAR 不得纳入、交付或准入 `libmpv.so`，直到负责人确认联合审计结论。
- **理由**：产物位置决定 HAR 内容、HAR 与私有原生层边界、加载失败语义、ABI/ELF 审计范围以及 GPL 精确对应源码责任，不能由计划阶段猜定。
- **候选方案**：
  - A：将经审计的 `libmpv.so` 随 HAR 受控本地分发。
  - B：由经审计的私有原生层受控提供，HAR 仅经已确认边界使用。
  - C：材料或审计链不完整时拒绝候选。
- **比较维度**：构建输入锁定、HAR/私有层边界、加载位置/顺序/失败行为、ABI、ELF `NEEDED`、导出符号、动态依赖 allowlist 与 denylist、精确对应源码、构建脚本、许可证、NOTICE、SBOM、双次可复现构建、同候选的真机能力证据。
- **自动化审计**：来源锁与摘要一致性、构建 manifest、SBOM、NOTICE、许可证策略、ELF 依赖/符号、产物 SHA-256 可复现性、证据 JSON 结构与必填字段。
- **人工审计与确认**：最终加载边界、失败语义、ABI/ELF allowlist、GPL 对应源码与材料完整性、真机证据真实性、候选准入签收。
- **停止条件**：任一强制材料、审计结果或负责人确认缺失；脚本审计失败；候选使用非 libmpv 内核或 AVPlayer 回退；或把“已构建待验证”写成支持。

## 决策 3：Surface/XComponent、线程与首期媒体输入

- **决定**：公开生命周期和媒体输入范围仅保留“暂定/待证实”描述；先执行不预设所有权或线程模型的目标真机 spike。
- **理由**：现有 ArkTS 契约和 native 探索代码只能说明候选边界，尚不能说明有效 Surface 的所有权、resize 语义、线程交接或真实首帧。尤其 `resizeSurface` 是否存在一一对应的原生实现不可假设。
- **Spike 观察矩阵**：

| 场景 | 记录项 | 通过判据（仅供负责人确认） |
| --- | --- | --- |
| attach | 当前 generation、尺寸、NativeWindow/EGL 取得结果、线程、事件序列 | 仅当前有效画面可成为渲染目标 |
| resize | 新旧尺寸、原生调用/重建、首帧连续性、资源计数 | 语义可解释且无陈旧画面接管 |
| detach | generation、停止渲染时机、回调丢弃、资源计数 | 旧画面不再渲染或接收事件 |
| destroy/rebuild | 创建销毁顺序、generation、线程、恢复结果 | 新画面唯一接管，旧资源释放 |
| release | 重复调用、线程 join、释放后控制与回调 | 无崩溃、死锁、残留画面或悬垂事件 |
| 媒体样本 | 样本 ID、脱敏 URI、协议/容器/编码、结果 | 仅批准闭集可升级为首期能力 |

- **候选公开边界**：可暂定描述 `attachSurface`、`resizeSurface`、`detachSurface`、`load`、`play`、`stop`、`release` 和订阅事件，但所有接口必须标记为“待证实”，不得承诺其渲染或首帧结果。不得暴露 NativeWindow、EGL、原生句柄或线程对象。
- **停止条件**：没有 NativeWindow/EGL/GLES 真路径的可复核首帧；所有权、resize 或线程模型无法解释；generation 混淆、重复渲染线程、释放后回调；首期媒体闭集未获确认；或只能用 PixelMap/NAPI probe/内存状态机佐证。

## 跨门禁共同研究输出

每个 spike 必须产生：可重放步骤、环境前提、候选 HAR 与源提交、证据文件清单及摘要、脱敏日志、失败记录、已知限制、能力三态、负责人决策请求。任何一项缺失均维持 No-Go。
