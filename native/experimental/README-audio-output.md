# S37 独立音频输出实验

这些源文件尚未进入生产补丁链。对应 Spec017 S37 / T067。不得将使用诊断核心生成的本地 HAR 当作最终 CI 交付。

## 所有权与有界恢复

`audio_output_adapter.c`拥有两个固定输出槽、各一个平台控制线程和各一个固定PCM存储。有效队列容量为两个20ms周期。平台回调只复制有界PCM或输出零，不持有mpv/AO对象、不调用平台IPC；平台创建、时钟、Flush、Stop和Release均在控制线程。每个AO仅持有不可复用的租约代号。

关闭立即拒绝旧代/旧租约写入，清空软件旧PCM。平台先Flush丢弃缓存，再Stop、Flush及确认STOPPED；只有完整成功才能归还音频登记槽。失败或永久未返回的调用保留所有权，不以超时伪造静止，不强行释放。健康同格式输出复用；无租约时停止，不以长期静音占焦点。完整有序声道布局参与复用匹配。

确认停止后的Release入口挂起只占一个固定输出线程；另一个健康输出可以服务后续多个视频。这里避免了每条视频都创建、释放平台输出，并不承诺两个独立输出均坏死后仍有第三个输出。未知Stop/Flush/查询挂起仍不能安全恢复，系统级故障可信判定也尚未实现。

## 暂停、跳转与时钟

系统强制暂停保留待播PCM；系统恢复提示不会自动Start。明确恢复后才启动。平台控制尚未返回时回调不会继续送旧音。租约更换清除上一租约的本地暂停状态；真实平台迟到中断与路由变化仍须补设备资格测试。

异步reset不能仅报告零容量：mpv的push线程在尚未streaming时可能无限等待。reset后新PCM可进入原有有界暂存，Start意图保留至清空成功；确认前绝不送出。新的detach会丢弃暂存并取消Start；新的焦点暂停也能取消Start。没有新增通知线程或扩大缓存。

播放延迟包含软件队列和平台未播放帧。位置0不外推已播放量；暂停时保留最后确认位置，不能把整个历史累计帧数重新算为待播。时钟失效、重路由和物理屏幕/扬声器同步仍不能仅靠录制锚点判定通过。

## 验证与构建

运行 `python3 -B native/tests/host-survival/run-audio-adapter.py --out /tmp/audio-adapter.json`。平台替身在各独立进程中测试正常复用、旧写入拒绝、暂停/焦点、未确认Stop、Flush错误、一次Release挂起后复用、格式切换、时钟及异步reset竞态；使用ASan/UBSan。正常宿主门禁已纳入此入口。

实验核心将`ao_ohaudio_shared.c`映射为准备目录中的`audio/out/ao_ohaudio.c`，复制适配器的c/h并在Meson源列表加入c文件、链接`hilog_ndk.z`。不修改FFmpeg。诊断钩子只用于受控实验：`release-probe.mp4`在已停止后的Release入口永久等待；`global-probe.mp4`使用原有计时终局钩子。必须检查实际入口日志，不能只按加载次数计故障。

API20及以上动态注册新版写入/中断回调，API19使用旧版组合回调；API19设备尚未验证。完整本地Player HAR与诊断HAP逐库核验，后续生产接入必须另行通过iMac CI及设备/消费端门槛。详见`specs/017-host-survival/device-evidence/t067-diagnosis.md`。
