# 变更日志

本文记录 `@vidall/player` 的重要变更。

## 未发布

### 修复

- Issue #79 真机验收：缓存字节改为整张 NODE_MAP 读取，缺失的磁盘缓存成员标为不可用；时长和进度明确标记为估算，覆盖无长度直播流的动态时长。

### 新增

- Issue #79：按需异步 `getDiagnostics()` 及强类型快照，覆盖输入/输出媒体参数、丢帧、同步、缓存、表面与版本信息；包含可用状态、单位、来源、采集耗时和生命周期保护。
- 字节与累计帧数保留 int64 十进制精度；任意文件名/标题隐去，位深明确不支持。现有事件格式及版本号保持不变。
- 真机取值和采样性能待消费端协调验证，详见 `docs/playback-diagnostics.md`。

### 变更

- 将目标分发许可调整为 `GPL-3.0-or-later`，以匹配包含 libmpv 和静态 Samba SMB 路径的分发义务。
- 明确播放器仅以 libmpv 为目标内核，不使用 HarmonyOS AVPlayer。
- 暂停 OHPM 上传；当前包仅供本仓库独立 fixture 开发期验证，不修改或依赖 VidAll_TV。
- 将公开 API 限定为已文档化的播放器契约；其余 mpv 能力须经实现和验证后再公开。

## [0.1.0] - 2026-08-02

### 新增

- 面向 HarmonyOS TV 和手机应用的初始 ArkTS HAR 候选包。
- 公开 `createPlayer` 工厂，以及 `VidAllPlayer` 生命周期、播放、轨道、字幕、事件和错误 API。
- Surface 生命周期 API，以及本地文件、HTTP(S)、HLS 和 DASH 输入路径校验。
- 中英文使用文档、GPL-3.0-or-later 许可证文本和 OHPM 包元数据。

### 已知限制

- 当前 HAR 含候选 libmpv 原生 bridge，但 G1/G2/G3 尚未关闭，不能声明或交付真实播放能力。
- 设备相关编解码器、协议、硬解和性能行为仍需在目标设备验证。
- `smb`、缓存请求、裁剪、去隔行和截图均不属于稳定支持能力。
